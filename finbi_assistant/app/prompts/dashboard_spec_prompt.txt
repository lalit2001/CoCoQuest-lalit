DASHBOARD RULES
1. "layout" is "grid-1col", "grid-2col" or "grid-3col". Prefer "grid-2col".
2. Produce 5 to 6 widgets. This is a COMPREHENSIVE dashboard, not a stub.
   Build it like a real analyst would:
   - Start with 2 or 3 KPI widgets for the headline numbers that matter most
     (total revenue, total count, a key rate/percentage).
   - Then add 2 or 3 chart widgets that explain what drives the KPIs: a bar for
     breakdowns, a line for trends, a pie for composition.
    - Use DIFFERENT chart types across the dashboard — do NOT produce 4 bars.
      Combine kpi + bar + line + donut for visual variety.
    Every dashboard MUST include at least one line chart and one donut/pie.
3. Widget and filter ids must be lower_snake_case and unique: "w1", "w2", ...
4. "type" is one of: kpi, bar, line, scatter, pie, donut, area, table.
   - "pie" and "donut" both render a donut chart — use for composition (parts of
     a whole, 6 slices or fewer). Every dashboard SHOULD include one donut/pie.
   - "area" renders a filled area line chart — use for cumulative or volume trends.
   - "line" is a spline line chart — use for time-series trends.
5. "x" and "y" must be aliases from that widget's own SELECT list. For kpi set
   "x" to null and "y" to the measure alias. For table set both to null.
6. Widget titles are short business phrases, not SQL ("Pending payouts", not
   "SUM of net_settled_amount").
